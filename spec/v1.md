# Source 2 DiffMod Spec — Version 1

Status is draft.

## Introduction

Source 2 mods ship as VPK packs with compiled sources.
A VPK hides what it edits.
Two VPKs that touch one file clash, and the last load wins.
Each game update breaks VPKs, and authors must reissue each pack by hand.

A DiffMod holds plain diffs over decompiled sources.
A diff shows what it edits.
Builders merge DiffMods at build time and flag clashes with text conflicts.
A DiffMod often still applies after a game update, since a rebuild runs it past fresh sources.
If it fails, the diff marks the exact spot that needs care.

## Specification

The key words "MUST", "MUST NOT", and "RECOMMENDED" in this text state strict rules.

1. A DiffMod is a UTF-8 text file with LF line ends.
2. Keep one DiffMod per file.
3. The header holds zero or more lines at the top of the file.
Each header line starts with `#`.
The header ends at the first line that starts without `#`.
4. The keys are `spec`, `title`, `game`, `game-build`, and `decompiler`.
Builders ignore unknown `#` lines.
Builders treat them as comments.
Compound values use the `name/version` form.
All header keys are optional.
5. The `spec` key holds the spec name and version, for example `spec: source2-diffmod/v1`.
A file without a `spec` key defaults to `source2-diffmod/v1`.
If you add a header, place `spec` first.
6. The `title` key holds a short human name.
The `game` key holds the game id, for example `deadlock`.
The `game` key routes the DiffMod to a profile.
Builders with one game ignore it.
The `game-build` key is RECOMMENDED and holds the game build id.
The `decompiler` key is RECOMMENDED and holds a registry id plus a version, for example `source2viewer-cli/20.1`.
Take ids from `decompilers.md`.
7. The body is a unified diff.
Use `diff -u` form with `---` and `+++` lines.
The body MUST apply clean with `git apply -p1`.
8. Paths MUST use `a/` and `b/` prefixes.
Paths MUST stay relative to the VPK root.
New files MUST use `--- /dev/null` plus `+++ b/<path>`.
Version 1 forbids renames.
Version 1 forbids deletes.
Use LF line ends in hunks.
9. Each target path MUST map to a compiled path through the game profile.
Each profile lists its own map.
The next table shows the Deadlock map.
Files with a raw suffix such as `.cfg` pass through with no compile step.
If no map row fits a target, fail the build.
Name the suffix in the error.

| Cleartext suffix | Compiled suffix |
| --- | --- |
| `.css` | `.vcss_c` |
| `.xml` | `.vxml_c` |
| `.js` | `.vjs_c` |

10. Decompile each target from the game VPKs.
Apply DiffMods in the order the user gives.
If two DiffMods touch the same hunk, fail the build.
Compile each result with the game resourcecompiler.
Pack compiled outputs plus raw files into one VPK.
11. The builder MUST record the game build ID from `steam.inf`.
The builder MUST record the decompiler id and version.
The builder MUST record the spec version.
Keep this record in the build log.
Builders MUST NOT need the `decompiler` key to build.
Warn on mismatch is RECOMMENDED.
Fail on mismatch is allowed but not RECOMMENDED.
12. Spec version 1 covers Deadlock.
The core stays game neutral.
New titles need a profile and a build test.
Send profiles as spec pull requests.
13. Spec versions use plain integers with a v prefix: v1, v2, v3.
Builders warn on unknown spec versions and proceed.
A new integer marks a break in form or build acts.
Freeze each released version.
Never edit a frozen version.
If you fix a typo, add an erratum in the changelog.

## Advisory

This section is advisory, not strict.

Keep hunks small.
Small hunks survive game updates.
Large ones clash.
Prefer style edits over layout edits.
Style rules clash less than moved panels.
Never ship full game files.
Ship diffs alone.
Full files hide Valve edits.
Name titles plainly.
The title key serves mod lists and managers.
Name stored DiffMods with the `.patch` suffix.
Keep three lines of context.

## Example

A header looks like this:

```text
# spec: source2-diffmod/v1
# game: deadlock
# decompiler: source2viewer-cli/20.1
# title: Always show ability suggestions
```

## Profiles

The Deadlock profile lives in `profiles/deadlock.md`.
Version 1 has no more profiles.
The core still fits more titles.
A new profile needs VPK paths, a suffix map, and a green build test.

## FAQ

**Why diffs and not full files?**
Full files hide Valve edits and clash on each shared file.
Diffs show edits and merge.

**Does one DiffMod cover many files?**
Yes.
One DiffMod holds edits to any count of targets.

**What if a DiffMod fails to apply?**
Re-derive it from fresh sources.
The old diff shows the prior intent.

**Why the `.patch` suffix?**
Diff tools and builders read it with no extra setup.

**What about CS2 or Dota 2?**
Version 1 covers Deadlock alone.
The core fits more titles with Panorama sources in VPKs.
Each new title needs a profile and a build test.

**Why pin the decompiler?**
Decompile output shifts with the decompiler release.
A pinned version keeps builds repeatable.

**How do new decompiler names get issued?**
Send a pull request that adds one registry row.
Take the first free slug.
The id maps to one tool and one release line.

**Does a new decompiler need a new spec version?**
No.
New rows extend the registry, not the form.
Old files still validate, so the version stays.

**Does a new file type need a new spec version?**
No.
New suffixes extend the profile, not the form.
Prove a full round trip first: decompile, edit, compile, load.
Send the map row as a profile pull request.

**Do builders enforce the header?**
Builders read what they need and skip the rest.
Warn on unknown spec versions and proceed.
Warn on decompiler mismatch is RECOMMENDED.
