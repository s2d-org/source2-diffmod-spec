# SV2 DiffMod Spec — Version 1

Status is draft.

This spec defines the DiffMod form for Source 2 Panorama changes.
A DiffMod edits decompiled game sources.
A builder turns a DiffMod into a VPK.
Authors merge DiffMods with plain diff tools.

## 1 Terms

A DiffMod is a text file with a header and a diff body.
A builder is a tool that turns DiffMods into a VPK.
A profile is a short record with facts per game.
A target is a game file that a DiffMod edits.
A VPK is the game pack that holds compiled sources.

## 2 File form

A DiffMod is a UTF-8 text file with LF line ends.
Name DiffMod files with the `.patch` suffix.
Keep one DiffMod per file.

## 3 Header

The header holds zero or more lines at the top of the file.
Each header line starts with `#`.
The keys are `spec`, `title`, `game`, `game-build`, and `decompiler`.
Builders ignore unknown `#` lines.
Builders treat them as comments.
The `spec` key holds the spec version, for example `spec: 1`.
A file without a `spec` key defaults to version 1.
The `title` key holds a short human name.
The `game` key holds the game id, for example `deadlock`.
The `game-build` key holds the game build id.
The `decompiler` key holds the decompiler name and version.
Example: `decompiler: source2viewer-cli 20.1`.
If you add a header, place `spec` first.

## 4 Body

The body is a unified diff.
Use `diff -u` form with `---` and `+++` lines.
The body MUST apply clean with `git apply -p1`.
Paths MUST use `a/` and `b/` prefixes.
Paths MUST stay relative to the VPK root.
New files MUST use `--- /dev/null` plus `+++ b/<path>`.
Version 1 forbids renames.
Version 1 forbids deletes.
Keep context at three lines.
Use LF line ends in hunks.

## 5 Target map

Each target path MUST map to a compiled path through the game profile.
The Deadlock profile maps `.css` to `.vcss_c`.
It maps `.xml` to `.vxml_c`.
It maps `.js` to `.vjs_c`.
Files with a raw suffix such as `.cfg` pass through with no compile step.

| Cleartext suffix | Compiled suffix |
| --- | --- |
| `.css` | `.vcss_c` |
| `.xml` | `.vxml_c` |
| `.js` | `.vjs_c` |

## 6 Build

Decompile each target from the game VPKs.
Apply DiffMods in order.
If two DiffMods touch the same hunk, fail the build.
Compile each result with the game resourcecompiler.
Pack compiled outputs plus raw files into one VPK.

## 7 Reproducibility record

The builder MUST record the game build ID from `steam.inf`.
The builder MUST record the decompiler name and version.
The builder MUST record the spec version.
Keep this record in the build log.

## 8 Profiles

Each game needs a profile.
A profile lists VPK search order, suffix map, raw suffixes, and compiler notes.
Deadlock is the reference profile.
Other titles stay draft until a build test passes.

## 9 Version rule

Spec versions use plain integers: 1, 2, 3.
A new integer marks a break in form or build acts.
Freeze each released version.
Never edit a frozen version.
If you fix a typo, add an erratum in the changelog.
